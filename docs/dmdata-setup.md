# DMDATA APIキーの設定方法

QuakeWatch ver15の「DMDATA（自分のAPIキー）」は、利用者が自分のDMDATA契約とAPIキーで公式APIへ直接接続する方式です。この直接接続で開発者のキー共有や予報データの再配信は行いません。別途準備する共有受信は警報・通常地震情報だけが対象で、予報は含めません。[共有サーバーの管理者向け手順](dmdata-shared-server.md)を参照してください。

## 友達へ共有するとき

共有するのは [QuakeWatch ver15のURL](https://nekokun148.github.io/quakewatch-v15/) です。APIキーは共有しません。

| 利用のしかた | 必要な設定 |
| --- | --- |
| サイトを開いて見るだけ | DMDATAのAPIキー・許可ドメインの設定は不要です。DMDATAの直接受信とは別です。 |
| 自分のDMDATA契約で速報を受信する | 本人のAPIキーを入力し、本人の契約・キーの権限に合う配信区分を選びます。 |
| 自分のキーにドメイン制限を設定している | そのキーの設定で、この公開サイトのホスト名を一度許可します。 |

**共有相手が増えるたびに、サイトを紹介する人のAPIキーへ登録を追加する必要はありません。** 許可ドメインは「誰にサイトを見せるか」ではなく、「どのWebサイトから、そのキーを使えるか」の設定です。友達が自分のキーを使う場合は、友達自身がそのキーを設定します。

同じ公開サイトを使う間は、ドメインを毎回入力するものではありません。ただし、キーを作り直したりサイトのホスト名が変わったりした場合は設定を再確認します。契約済みであっても自動連携はせず、接続操作が必要です。

## 接続の準備

1. [DMDATA管理画面](https://manager.dmdata.jp/)へ、自分のアカウントでログインします。
2. 自分の契約で利用できる緊急地震速報の配信区分を確認します。予報は `eew.forecast`、警報は `eew.warning` です。契約がない区分は受信できません。新しい契約や課金は、このアプリでは行いません。
3. 管理画面の「APIキー・OAuth」から、このアプリ用のAPIキーを作成します。既存キーを利用する場合も、次の権限を確認します。

| アプリの配信区分 | 必要な権限 |
| --- | --- |
| 予報 | `socket.start`、`eew.get.forecast` |
| 警報 | `socket.start`、`eew.get.warning` |
| 予報＋警報 | `socket.start`、`eew.get.forecast`、`eew.get.warning` |

4. 許可ドメインを制限している場合は、公開サイトのホスト名 `nekokun148.github.io` を確認します。ドメイン欄にURLの `https://` や `/quakewatch-v15/` は含めません。許可IP・ドメインの制限をむやみに解除せず、接続元に必要な範囲だけを設定してください。
5. [QuakeWatch ver15](https://nekokun148.github.io/quakewatch-v15/)で「DMDATA（自分のAPIキー）」を開き、伏せ字入力欄へ自分のキーを入力します。
6. 契約・権限に合った配信区分を選び、「接続」を押します。「接続済み・速報待機」が表示されるまで、DMDATA受信中とは扱いません。

権限変更の反映には最大5分かかる場合があります。JQuakeなど他のアプリも利用している場合は、WebSocketの同時接続枠に空きがあることを確認してください。何度も接続ボタンを押したり、他のアプリの接続を勝手に切断したりしないでください。

## 許可ドメインの入力例

自分のキーにドメイン制限を設定している場合、[DMDATA管理画面](https://manager.dmdata.jp/)の「APIキー・OAuth」で、そのキーの「許可ドメイン」を確認します。GitHub Pages版のホスト名は次の文字列です。

```text
nekokun148.github.io
```

- `https://`、末尾の `/`、`/quakewatch-v15/` は含めません。
- `127.0.0.1` はローカル版の接続元です。GitHub Pages版とは異なります。
- 登録するのは友達の名前・端末名・メールアドレスではありません。
- 許可IPを別途制限している場合は、その制限にも従う必要があります。ドメインだけで必ず接続できるとは限りません。
- 制限の一括解除やワイルドカードによる広い許可は、この手順では案内しません。この公開サイトから自分のキーを使うために必要な範囲を確認してください。

## 配信区分の選び方

| 自分の契約とキーで利用できる区分 | アプリで選ぶ表示 |
| --- | --- |
| 予報のみ | 緊急地震速報（予報） |
| 警報のみ | 緊急地震速報（警報） |
| 予報と警報の両方 | 緊急地震速報（予報＋警報） |

予報だけが利用できるのに「予報＋警報」を選ばないでください。アプリが契約やキーの権限を自動で追加することはありません。契約状況や接続枠は各自のDMDATA管理画面で確認します。

## キーの取り扱い

- 自分の契約のキーだけを使用してください。他の人のキーの共有は行いません。
- 公開版はキーをブラウザ保存・URL・GitHub・ログへ記録しません。接続中と再接続待機中だけ、ページのメモリで保持します。
- 接続操作後は入力欄を消去します。切断・ページ終了・認証などの致命的エラーでは、受信処理の保持キーも消去します。
- 再読み込み後は、再度自分で入力して接続します。ページを開くだけではDMDATAへ接続しません。
- APIキーをチャット、スクリーンショット、SNSなどへ載せないでください。端末やページ上のスクリプトが侵害されている場合まで安全を保証するものではありません。

## 接続できない場合

| 表示 | 確認する内容 |
| --- | --- |
| 認証失敗 | キーが有効か、入力が正しいか |
| 対象区分の契約なし | 選択した配信区分の契約 |
| 権限・接続元を確認 | 必要な権限、許可ドメイン・IP |
| 同時接続数の上限 | 他のアプリも含むWebSocket接続枠 |
| 通信・接続情報の確認に失敗 | 通信状態、ブラウザからの接続許可、公式サービスの稼働状態 |
| レート制限 | 時間を置いて待機。連続操作で回避しない |

### 「権限・接続元を確認」と表示されたとき

この表示はHTTP 403の案内です。公式仕様では権限不足と接続元の制限がどちらも403になるため、この文言だけで原因を断定しません。

1. 選択した配信区分に対し、前述の `socket.start` と対象区分の権限・契約があるか確認します。片方しか利用できない場合は、その区分だけを選びます。
2. キーにドメイン制限がある場合は `nekokun148.github.io`、IP制限がある場合は現在の接続元が許可対象か確認します。APIキーや接続元IPをチャットへ送る必要はありません。
3. 設定を変更した場合は最大5分待ち、アプリへ自分のキーを再入力して「接続」を一度押します。
4. 解決しない場合は、キーや認証情報を伏せて、表示された状態と選択した配信区分を確認します。認証ヘッダー、接続チケット、APIキーを含む画面やログは共有しません。

接続操作後にキー入力欄が空になるのは、公開版の仕様です。入力が消えたことだけで接続失敗とは判断せず、下の状態表示を確認してください。

DMDATAの開始通知を確認するまでは既存のYDITS/Wolfx経路を維持し、切断・エラーでも既存経路へ戻します。気象庁の観測情報と強震モニタの取得は別経路で続けます。

## 情報の扱い

表示するEEWの震度は気象庁の予測であり、実際の観測震度とは別です。P/S波は受信した通常の震源情報からの簡易到達予測で、PLUM法のみ・仮定震源・発生時刻や座標の欠測時は開始しません。警報電文のマグニチュードと深さは表示しません。地震情報には誤報や予測誤差、通信遅延があり、表示や音声の到達を保証しません。避難判断や危険な機器の制御を、このアプリだけに依存しないでください。
