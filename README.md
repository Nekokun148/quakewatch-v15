# QuakeWatch ver15

## 台湾の地震情報（許可制）

「台湾情報の受信を許可」を利用者がONにした間だけ、中央氣象署の公式RSSから地震の見出しを60秒ごとに確認します。初期OFF・許可は保存しません。公式へのリンクと原文の見出しだけを別欄に表示し、日本の地震・EEW・P/S・音声と混在させません。利用条件、掲載範囲、ローカルサーバーの再起動と公開用Worker更新については[台湾情報の説明](docs/taiwan.md)を参照してください。

## Wolfx障害時代替

YDITSのサーバー1、2、3が順に失敗した場合だけ、Wolfxの日本向けWebSocket `wss://ws-api.wolfx.jp/jma_eew` を使用します。YDITSから正常な応答が戻ればWolfxを停止します。P2Pへの切り替えはありません。初回問い合わせは接続時の1回だけで、切断時は5秒から最大60秒の間隔で再接続します。

過去の最終受信情報は現在の地震として表示・警報・読み上げしません。訓練も自動警報しません。受信した震源座標が有効な場合のみ既存の簡易P/S到達予測を使い、仮定震源要素や欠測から座標・観測震度を作りません。提供元の切り替え時は受信した発生時刻で同一イベントの警報重複を抑制しますが、同時刻の別地震の完全な識別は保証しません。

Wolfxは非公式サービスです。参考表示であり、公式の防災情報や避難判断を代替しません。[API仕様](https://wolfx.jp/docs/open-api/)・[WebSocket仕様](https://wolfx.jp/docs/websocket/)を参照してください。配布対象は scripts/build.mjs の PUBLIC_FILES で管理します。

地震監視Web（V15ベース）では端末の加速度センサー（DeviceMotion）を地震検出に使用しません。気象庁の地震情報・観測震度、YDITS APIの緊急地震速報を受信し、実際に発表された情報を表示・日本語で読み上げます。P2Pの常時監視は停止しています。

## 地図UI

地図はLeafletと同梱したNatural Earthの海岸線・国境データを使い、参考画像に合わせた暗色の全国地図にしています。強震モニタのリアルタイム震度／最大加速度の画像色、地震の震源、発表震度、速報、P/S到達予測を同じ地図に表示します。白い別地図はありません。Leafletを読み込めない場合は簡易地図となり、ライブ画像色の地理座標への重ね合わせは行いません。

陸上の丸は、防災科研の[公開観測点リスト](https://www.kyoshin.bosai.go.jp/ja/stationlist/)にあるK-NET・KiK-netの位置を使用します。2026-10-06取得時点で休止と表示されている地点を除き、陸上1,728地点と海上6地点を同梱しています。北海道から沖縄・離島まで47都道府県に分布します。

海底は[防災科研の海底観測点情報](https://www.seafloor.bosai.go.jp/st_info/)の2026-10-07時点の設置座標243地点（S-net 150、DONET1 22、DONET2 29、N-net 36、相模湾6）を使用します。S2N13は公開一覧のS2N13Aを使用します。合計1,977地点です。海底の青い輪と陸上の灰色点は未受信を示し、平常状態や稼働状態を意味しません。観測点のツールチップに観測網・コード・受信時刻を表示します。

初期表示は全国が収まるよう、地図の大きさに合わせて縮尺を設定します。観測点の位置データは `js/stations.js` と `js/seafloor-stations.js` に同梱しているため、表示のたびに防災科研へ問い合わせません。

P波/S波は受信した震源情報と発生時刻からの概算到達予測です。一定速度P=6km/s、S=3.5km/sの簡易表示で、気象庁の走時表による正確な到達時刻ではありません。requestAnimationFrameで滑らかに描画し、毎フレームの実時刻から半径を計算するため、背景タブから戻っても時刻に追いつきます。10分で終了し、新しい震源では古い描画ループを解除します。波形からP/Sを判定するものではありません。

## 地図データ

Google Maps APIは使用しません。地図背景はNatural Earthの公開ドメインデータを同梱しており、APIキー不要です。詳細測量用の地図ではありません。出典・ライセンス・変換元URLは `THIRD_PARTY_NOTICES.md` と `data/` 内に記録しています。

## データ

- YDITS API: 緊急地震速報（警報）。サーバー1を最優先にし、失敗時だけ2、3へ切り替えます。P2P WebSocketとP2P履歴APIには接続せず、自動フォールバックもしません。
- 気象庁: 震源・震度情報の公開JSONを60秒ごとに確認。観測点の緯度・経度と震度を使い、発表された観測震度を色付きの丸で表示します。
- DMDATAは各自のAPIキーで直接受信できます。共有受信の追加構成は警報・通常地震情報だけが対象で、サーバーの準備・有効化が必要です。予報は共有しません。
- 防災科研の強震モニタ: 利用者から一般公開を含む取得・配信の許可取得済みとの申告を受け、「リアルタイム震度」「最大加速度」の公式画像を中継経由で表示します。ローカル版は同梱の中継、Pages版はCloudflare WorkersのHTTPS中継を使用します。画像の色を数値へ変換したり、別の観測網に値を割り当てたりしません。公開・再配信は取得した許可の範囲内で行ってください。

「揺れを観測した地域」は気象庁の発表をもとに都道府県・最大震度・地点数・時刻を表示します。白枠の大きい点は気象庁の観測震度、細かい色付き点は強震モニタ画像の色です。座標が含まれない情報を近くの観測点や地域の中心へ推測で割り当てません。同じ発表の座標なしデータで座標を消したり、古い発表で最新の点を上書きしたりしません。

地域一覧には受信した各地点・地域の観測震度を色付きで表示し、80件を超えても省略しません。次の地震では発生時刻・震源名・一覧を入れ替え、観測震度がまだ届いていない場合は発表待ちと表示します。同じ地震の震源情報だけが続報として届いた場合は、受信済みの観測震度を保持します。座標未確認の地点も一覧には表示しますが、地図上の位置を推測で補いません。

**数値の毎秒取得は未対応です。** 強震モニタ画像の色を、観測点IDと座標が一致する地点へ表示します。画像上のピクセル対応はMITライセンスのコミュニティ資料で、公式APIの保証ではありません。移設後の座標差・対応不明・同じピクセルを共有する地点は除外します。画像のサイズ変更はエラーにし、透明・白黒のピクセルを観測値として扱いません。色を震度／Gal値に逆算したり、色から地震を検出・通知したりしません。S-net等へ陸上の色を流用しません。正確な数値表示には許可済みの観測点ID・計測値・時刻の配信仕様が必要です。

## 強震モニタと時刻

地図の黄緑の強調表示は、気象庁の震源・震度情報に震度1以上の観測が含まれる場合だけ自動で出します。画像色の変化、利用者の揺れ報告、訓練・模擬データ、緊急地震速報だけでは新規表示しません。アプリが地震の実在を独自に保証するのではなく、公式観測の発表を条件にする方式です。既存の速報・警報音・読み上げ・P/S波は別の処理のまま維持します。

新しく受信した地震情報の震源名・深さ・M・発表時刻を地図上に表示します。数値は受信値のみで、欠測は未受信とし、実座標のある震源と観測点だけに輪を出します。初回の過去情報・120秒より古い発表・履歴の再表示は新規の地震発生扱いにしません。次の地震で入れ替え、対象を対応できる取消や履歴選択で消去します。通常の画像色変化は右側の一覧だけに残します。地図の自動移動や位置・震度の推定は行いません。ローカルの確認用 `tests/quake-highlight-20261020/` は明記した模擬値を使う独立ページで、本体へ模擬地震を送らず、公開ビルドにも含めません。

全国地図の上部で「リアルタイム震度」「最大加速度」を切り替えます。観測点の色と公式スケールだけが変わり、地図・震源・速報・拡大位置は維持されます。右の欄は地震情報・速報・観測地域専用です。スマートフォンでも同じ統合地図を表示します。

「リアルタイム震度」「最大加速度」を選ぶと、地表の公式画像を1秒ごとに確認します。前の取得が終わるまでは次の取得を開始せず、非表示のタブでは取得を休止します。同じ観測時刻の画像は再読込しません。観測時刻をJSTで表示し、遅延や取得失敗は状態欄に表示します。画像の更新失敗時は最後の画像を残すため、必ず観測時刻も確認してください。

更新は時計・観測点の色・観測時刻・状態欄だけを書き換え、全体の自動リロードはしません。色が変わった地点だけスタイルを更新し、地図・音声コントローラーは作り直しません。取得失敗時は最後の色と観測時刻を残してエラーを表示します。指標の切り替え時には古い指標の色を消し、受信前に誤表示しません。

「強震モニタの変化」は連続した新しい画像で同じ地点の色が変わった場合に、対応が確認できた観測点の名前を表示します。初回・指標変更・欠測・遅延・重複画像は検出扱いにしません。これは画像色の差であり、地震発生・震源・数値の震度の確定ではありません。速報のカードや警報音、P/S波とは別の「地震・震源未確定」の表示で、色の変化だけでは警報を鳴らしません。

画面上部の現在時刻は端末の時計を使い、日本標準時（JST）で1秒ごとに更新します。観測時刻・地震の発生時刻とは別です。ブラウザが休止中の場合、更新は再表示時に追いつきます。端末の時計がずれている場合は現在時刻もずれます。

[強震モニタの説明・利用条件](https://www.kyoshin.bosai.go.jp/ja/about_kmoni/)にあるように、リアルタイム震度は通常の観測震度と同じではなく、地震以外の振動が表示される場合もあります。このアプリを避難判断の唯一の情報源にはしないでください。

## 緊急地震速報と警報音

警報音は初期状態でOFFです。公開版はWeb Audioで生成する約2.6秒の上昇3連音を使います。ONへの切り替えだけでは音を鳴らさず、新しく受信した対象の速報または利用者の「警報音テスト」操作で1回再生します。利用者指定の `nc239566` MP3は作者・公開利用条件が未確認のため、公開リポジトリ、公開ビルド、Service Workerのキャッシュへ含めません。別のローカル作業コピーの指定MP3は変更していません。

ゲイン上限は0.14です。スピーカーによって聞こえる大きさは異なります。同一報の重複・過去履歴・訓練・取消は鳴らさず、予報から警報への更新や最大震度上昇は再通知します。取消時とOFF時は再生を停止します。ブラウザの再生制限、消音、スピーカーの状態によって実際には聞こえないことがあるため、利用者の操作でテストしてください。公式の緊急地震速報チャイムとして提供するものではありません。

右の情報欄には受信した予報・警報・報数・最終報・取消、予測地域の震度を表示します。震度1は青、2は緑、3は黄、4はオレンジで、5弱以上も段階別に色分けします。震度不明は灰色です。PLUMの識別情報がある地域は「PLUM」と表示し、到達時刻やP/Sリングを推測で補いません。このアプリが独自にPLUM法を計算する機能ではありません。

警報音と読み上げが両方ONの場合、警報音の自然終了後に「強い揺れに警戒してください。」を読み、その後に最新の速報内容を読みます。音の再生中に届いた続報は最新の内容へ置き換えます。取消・警報音OFFでは終了後の注意文を取り消し、読み上げOFFを自動でONにすることはありません。警報音が無効または再生できない場合も、読み上げONなら速報内容の読み上げを継続します。

### YDITSの監視と制約

[公式API仕様](https://www.ydits.net/api/)と[警報の仕様](https://www.ydits.net/api/vxse43/)で公開されている次の本番URLを使用します。WebアプリのHTMLを地震データとして取得するものではありません。

1. `https://api.ydits.net/vxse43`
2. `https://api2.ydits.net/vxse43`
3. `https://api3.ydits.net/vxse43`

サーバー1が正常なら他には接続しません。HTTPエラー、通信失敗、異常なJSON、古い配信時刻などで1が使用できない場合にだけ2、さらに3へ切り替えます。バックアップ中は60秒ごとに1の復旧を確認し、正常なら1へ戻します。取得完了から次の取得まで最低1秒、同時取得なし、1要求の期限は5秒です。全サーバー失敗時は30秒待ち、レート制限時は少なくとも30秒待ちます。レート制限を他サーバーや再接続で回避しません。非表示タブでは取得を休止します。

HTTP 200だけで正常接続とは判定せず、本文の `status: OK`、時刻、必要なフィールドを検証します。API内部エラー、JSON形式の不一致、通信失敗、タイムアウトは状態欄で区別します。続報の重複と古い情報による自動音声は抑制し、訓練・テスト報は本番と分けて表示します。受信した `isFinal` と `isLast` はそれぞれ「最終報」「更新終了」とし、報数を作りません。

現在の公開APIはベータ版で、利用可能なのはEEW警報のみです。通常の地震情報・観測震度は気象庁、観測画像は強震モニタを継続して使います。公開JSON仕様には震源座標・地域別予測・公式イベントID・報数が記載されていません。受信した発生時刻は内部の重複抑制にのみ使用し、公式のIDとは表示しません。取消の対象を受信履歴から対応できない場合、別の地震の警報や波を止めず「対象地震は未確認」と表示します。震源名から座標を推測したり、古い地震の位置を流用したりしません。YDITSだけでP/S波を描くことはできず、実際の座標を含む地震情報の受信が必要です。仮定震源要素はPLUM法の確定とは扱いません。

2026-10-10の実接続確認ではサーバー1の応答がHTTP 200でも `status: INTERNAL_ERROR` となり、有効な地震JSONの本番受信は未確認です。この環境から見た応答であり、サービス全体の障害やCORSが原因だとは断定しません。APIの正常応答がない間はEEWを監視できたと表示せず、取得に失敗した状態と次の接続先を示します。[YDITS for Web](https://webapp.ydits.net/)は別アプリで、公開されている実装ではP2P、Wolfx等を組み合わせています。このWeb版が開けることは、上記公開APIの正常配信を保証しません。

## 読み上げ

### クラウドVOICEVOX（任意・非公式）

音声・接続の操作は上部の「設定」にまとめています。初期表示は設定を閉じて地図を優先し、警報音・読み上げのON/OFFだけは常時表示します。PC/スマートフォンとも設定欄は高さを制限して独立スクロールでき、Escapeで閉じられます。受信状況・画像色の変化・凡例も開閉式ですが、閉じても既存の受信・警報・描画処理は停止しません。

今回のPagesワークフローは `node scripts/build.mjs --no-shared-dmdata` を使用し、準備中の共有DMDATA接続先を環境変数の有無にかかわらず無効にします。既存の個人キー直接受信は維持します。クラウド音声の追加を共有DMDATAサーバーの有効化とは扱いません。

公開版の「設定」にある「クラウドVOICEVOX（アプリ不要）」で、外部送信の説明と利用条件を確認して「外部送信に同意して使う」をONにした利用者だけが、APIキー不要の非公式tts.questを使えます。利用者のPCでVOICEVOXを起動・インストールする必要はなく、音声合成は外部サーバーで行います。他の利用者も同じ公開URLから自身で同意して使用でき、サイト管理者のPC内エンジンやDMDATAのAPIキーは共有しません。新しいクラウド契約は不要ですが、通信・ブラウザの音声再生機能が必要です。PC/スマートフォン/iPadの実機すべてでの動作は保証しません。

初期OFF・同意は保存しません。ページを開いただけでは音声サービスへ通信せず、ON時は固定の静的話者一覧だけを取得し、読み上げは開始しません。「話者一覧取得済み」は音声合成・再生の成功を意味しません。話者名とIDはサービスの一覧の値を使用し、「読み上げの声」で選択できます。選択した声だけは既存の音声設定として保存される場合がありますが、再読込後はクラウドを許可せずブラウザ標準で待機します。ページ離脱・復元時にも同意を解除します。

読み上げON後、読み上げ文と話者IDのみをHTTPSのPOST本文でtts.questへ送ります。DMDATAのキー、端末の緯度経度、Cookie、認証情報、ページのリファラーを付加しません。送信先には通常の通信情報（IP等）が伝わり、生成音声のURLを知る人は音声を取得できる場合があります。削除時期・送信内容の取り扱いは外部サービスに依存するため、機密情報を読ませないでください。

合成・状態確認・音声取得の合計待機は最大4秒、状態確認は1秒間隔で最大4回です。約2秒の3回目の確認で未完成でも、残りの期限内で待機を続けます。失敗・未完成・利用制限時は同じ文をブラウザ標準へ一度だけ引き継ぎます。応答期限超過・合成未完了・利用制限・通信失敗・応答形式不正を分けて表示し、再取得操作時には残りの待機秒数も表示します。通信失敗だけではCORSや回線等の原因を断定しません。エラー後は最低30秒、Retry-AfterまたはJSONのretryAfterが長ければそれ以上待ち、OFF/ONや再確認でも制限を回避しません。合成開始間隔は最低2秒で、連続した短文はブラウザ標準へ切り替わる場合があります。定期的な自動再接続はしません。クラウドは速報用の可用性や遅延を保証するサービスではありません。

警報音は従来どおり端末で即時再生し、完了後の注意文から音声処理を始めます。クラウドを待って警報音を遅らせません。OFF・取消・新しい速報による中断・同意解除で進行中の通信と古い再生を止め、遅れて届く音声を再生しません。ブラウザの自動再生拒否を迂回しません。既に送信された文のサーバー側処理や保存の中止・削除までは保証できません。音声データとクラウド応答はService Workerやローカルストレージへ保存しません。

サービスは[WEB版VOICEVOX API（低速）](https://voicevox.su-shiki.com/su-shikiapis/ttsquest/)と[提供元のAPI資料](https://github.com/ts-klassen/ttsQuestV3Voicevox)に基づきます。VOICEVOX公式サービスではありません。[VOICEVOXと各話者の利用条件](https://voicevox.hiroshiba.jp/)を守り、声の名前に表示するVOICEVOXのクレジットを保持してください。公開済みの実サイトでの接続確認・実音声・実機Safariは、模擬テストとは別に確認します。

### この端末のVOICEVOX

「このPCのVOICEVOXを優先」は新規利用者の既定でOFFです。ブラウザ標準または同意制クラウドだけで使う場合は、PC内のエンジンへの接続を試みません。以前の明示的な優先設定・端末内話者の選択は維持します。端末内優先がONのときだけ、読み上げON・音声テスト・最新情報の読み上げ操作で、同じ端末の `http://127.0.0.1:50021` への接続を一度試します。利用可能なら保存済みのVOICEVOX話者、なければエンジンが実際に返した最初の読み上げスタイルを次の読み上げから選びます。確認中はブラウザ標準の声を使い、接続確認のために現在の読み上げを中断しません。歌唱スタイルや存在しない声は追加しません。

VOICEVOXを選択した読み上げでは、公式エンジンの `audio_query`、`synthesis` の順に同じ端末へ文を送り、生成した音声をブラウザで再生します。接続不可・5秒の接続タイムアウトではブラウザ標準を維持します。VOICEVOX優先中に音声合成が失敗した場合も、対応するブラウザ音声へ同じ文を一度だけ引き継ぎます。自動再接続ループは行いません。ブラウザの再生許可拒否は迂回せずエラー表示します。OFF・速報の取消・警報音開始時は待機中の合成要求と再生を止め、使い終わった音声URLを破棄します。既存の「警報音の後に注意文、その後に最新の速報」という順序も維持します。

「ブラウザ標準」ボタン、端末内優先OFF、ブラウザの声の明示選択は次回も尊重します。従来保存済みのブラウザ音声選択も維持します。優先設定と選んだ声だけをブラウザ内へ保存し、保存不可でも今回の選択は使えます。ページを開くだけではVOICEVOXへ接続せず、読み上げもOFFです。「このPCへ接続」は起動中のPC内エンジンへの明示的な再試行と話者選択を行いますが、音声合成や再生はしません。

この端末内のVOICEVOX連携はPC限定のサポートです。PCでも同じ端末でVOICEVOX互換エンジンが稼働し、そのブラウザ・公開サイトからの接続が許可されている必要があります。インストール済みアプリの一覧は調査せず、別のPCのエンジンにも自動接続しません。ブラウザ標準や上記の同意制クラウドとは別の接続先です。

公式エンジンの既定CORSはローカルアプリ向けのため、GitHub Pagesのオリジンからは接続を拒否される場合があります。エンジンのCORS設定・ネットワーク公開・ブラウザ権限をこのアプリで変更することはありません。端末内モードの接続先は同じ端末の固定URLで、外部送信は上記のクラウド同意がある場合だけです。[公式VOICEVOX](https://voicevox.hiroshiba.jp/)、[公式エンジンの接続仕様](https://github.com/VOICEVOX/voicevox_engine/blob/master/README.md)、[公式CORS設定](https://github.com/VOICEVOX/voicevox_engine/blob/master/run.py)を参照してください。

### ブラウザ音声

ブラウザの Web Speech API を使用します。ページを開いた直後はOFFで、「読み上げ OFF」を押すと開始確認の音声を再生し、以後に受信した地震情報を自動で読み上げます。ページを再読み込みしたときは再度ONにしてください。「読み上げの声」でブラウザが利用できる日本語音声を選択できます。声の選択はこのブラウザのローカルストレージに保存し、次回も使います（保存が制限されている場合は今回のみ）。声の変更だけでは音声を鳴らさず、現在の読み上げを中断せず次の文から反映します。「自動選択」は従来どおり端末の日本語音声を優先します。保存した声が一時的に利用できない間は自動選択で読み上げを継続し、声が戻ったら選択を復元します。選べる声は端末・ブラウザによって異なり、オンライン音声には接続が必要な場合があります。

「音声テスト」で再生を確認でき、最新地震の「読み上げ」で表示中の震源・最大震度・規模・深さ・観測地域を再生できます。震度1・2の地震も対象です。起動時や再接続時の過去の履歴は自動では読み上げません。緊急地震速報は通常の読み上げに優先します。音声が使用できない場合は画面に理由を表示します。

## 小さい揺れ

受信した震度1・2の気象庁地震情報も表示・通知・読み上げの対象です。P2Pの「揺れた」報告は常時受信を停止しています。「揺れの報告」欄は新規の利用者報告が未受信であることを表示します。既存のローカル受信テスト用の処理は残しますが、本番でP2Pへ接続することはありません。

利用者の報告は震度未確定として表示し、気象庁の観測震度と区別します。このアプリは公開された情報を受信するもので、震度1未満の微振動を波形から独自に検出する機能はありません。

## 開発

このPCでは `start-preview.cmd` を実行すると、同梱済みのCodex用Node.jsでビルドし、5175番のプレビューを起動できます。インストール・キー発行は行いません。サーバーの画面は利用中開いたままにしてください。別のPCではNode.js 22以降を用意し、以下のコマンドを使用します。

Node.jsで `node scripts/serve.mjs` を実行し、`http://127.0.0.1:5173/` を開きます。別ポートを使う場合は `node scripts/serve.mjs 5174` と指定します。サーバーはローカルPCからの接続のみ受け付けます。

Node.js 22以降で `node --test tests/*.test.mjs` を実行します。`tests/browser.html` は模擬地震・感知報告・観測震度・速報の予報/警報/最終報/取消をローカルの画面にだけ注入する受信テストです。外部へ報告を送信しません。気象庁のテスト用JSONは[2026-10-07の公開報告](https://www.jma.go.jp/bosai/quake/data/20261007160547_20261007160305_VXSE5k_1.json)から必要なフィールドを抜粋しています。

「青森県東方沖 震度6弱テスト」は利用者指定の最大震度6弱・深さ80km・M7.4を、名前に「表示テスト・仮の震源」を付けて表示します。P/S表示用にテスト専用の北緯41度・東経143度を使い、発生15秒後から緑のP波・オレンジのS波リングを動かします。これは既存の一定速度による簡易予測で、深さ80kmを使った厳密な伝播計算でも実際の観測でもありません。このボタンは警報音・読み上げを再生しません。観測地点は追加せず、地図の通常の観測画像・既存の別震源とは区別します。

P波/S波リングをローカルで確認する場合は、URL末尾に `?demo=1` を付けるとテスト用震源を表示します。

青森のテストでは「模擬地域の現在震度」も200ミリ秒ごとに更新します。青森県・北海道南部・岩手県・宮城県のテスト専用代表位置に、白い点線枠の模擬マーカーを別レイヤーとして表示します。P波到達後は模擬震度1、S波到達後は試験用の固定推移で地域ごとの設定震度まで上昇し、その後0へ下がります。青森県の設定最大震度は6弱です。これは観測値でも地震動の物理予測でもなく、実際の観測地域一覧には混ぜません。再実行すると前の模擬タイマーとレイヤーを解除します。他の受信テストは「その他のテスト」から操作できます。

## GitHub Pages

APIキーや独自のシークレットは不要です。公開先のリポジトリ名が変わっても、HTML、ESモジュール、manifest、Service Workerは相対パスで動作します。

1. このプロジェクトの内容をリポジトリのルートに配置します。隠しフォルダ `.github/workflows/pages.yml` も含めてください。
2. GitHubの **Settings > Pages > Build and deployment > Source** を **GitHub Actions** にします。
3. デフォルトブランチへ反映するか、Actionsの **Deploy QuakeWatch to GitHub Pages** を手動実行します。

ワークフローはテスト後に `node scripts/build.mjs` を実行し、許可リストの静的ファイルだけの `dist/` を公開します。指定MP3、DMDATAのローカル認証・キー保存コード、共有サーバーの実装・秘密、テスト、開発スクリプト、環境ファイルは公開用ビルドへ含めません。標準のGitHub Pagesデプロイ権限を使用し、APIキーを発行しません。[GitHubの公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)も参照できます。

**GitHub Pagesだけでは強震モニタの中継サーバーを実行できません。** `workers/strong-motion.mjs` をCloudflare Workersの `quakewatch-v15-relay` として公開し、Pagesのオリジン `https://nekokun148.github.io` からのCORSを許可しています。取得先は防災科研の時刻JSONと既知のGIF画像に固定し、任意のURL、他サイトからのブラウザ利用、リダイレクト、異常画像を拒否します。画像は改変しません。現在の取得元までの通信はHTTPのため、この部分をHTTPSだと説明しません。

Pagesワークフローのビルド時だけ、公開設定 `KMONI_API_BASE=https://quakewatch-v15-relay.kouryou148.workers.dev/api/strong-motion/` をHTMLのbodyへ設定します。APIキーやトークンは使用しません。通常のローカルビルドは従来の同じPCの中継を使います。別の中継へ変更する場合は、この公開URLとWorkerのCORS許可オリジンを合わせてください。

Workers無料プランにはアカウント全体で1日100,000リクエストの上限があり、UTCの午前0時にリセットされます。毎秒の時刻確認と新しい画像の取得で、表示中の端末ごとに最大約2リクエスト/秒を使います。複数人の長時間利用や、上流サービス・回線・ブラウザの停止も含め、常時動作や速報到達は保証できません。キャッシュ・同時取得の集約・非表示タブの休止で無駄な取得を抑えますが、この上限をなくすものではありません。[Cloudflareの制限](https://developers.cloudflare.com/workers/platform/limits/)を参照してください。有料プランへの変更は別途利用者が判断してください。

ローカルで公開先と同じサブディレクトリ構成を確認する場合は、`node scripts/build.mjs` の後に `node scripts/serve.mjs 5175 --pages` を実行し、`http://127.0.0.1:5175/quakewatch-v15/` を開きます。PWAは同じプロジェクトの静的ファイルと背景地図だけをキャッシュし、外部の最新地震APIと強震モニタのAPI・観測画像はキャッシュしません。完全オフラインではライブ地震情報の取得はできません。

J-SHISの `https://www.j-shis.bosai.go.jp/map/api/postfix` と `labs/api/postfix` はURLの形式例です。postfixを[公式API一覧](https://www.j-shis.bosai.go.jp/api-list)にあるサービスのパスへ置き換えます。提供されるハザード・地盤情報は現在の揺れではないため、このアプリの毎秒観測値の取得先には使用しません。

公開先リポジトリは [Nekokun148/quakewatch-v15](https://github.com/Nekokun148/quakewatch-v15)、Pagesの共有先は [地震監視Web](https://nekokun148.github.io/quakewatch-v15/) です。表示名の変更でもURL・PWAの識別子・既存の設定キーは変更しません。実際の公開状態はActionsのデプロイ結果と公開画面で確認してください。

## ブラウザ標準の読み上げ

「ブラウザ標準」ボタンで保存済みのVOICEVOX選択を解除し、ブラウザが提供する日本語音声の自動選択へ戻します。切り替えだけでは音声を再生せず、読み上げON/OFF状態も変更しません。初めて利用する端末ではVOICEVOXや外部サービスのキーなしでブラウザ音声を自動選択します。VOICEVOXは明示的に選択した場合のみ利用します。日本語音声の提供状況は端末・ブラウザ依存で、オンライン音声の処理はブラウザの音声サービスに依存します。全端末での再生を保証せず、利用不能時は既存の状態欄に表示します。

## DMDATA（自分のAPIキー）

GitHub Pages版の「DMDATA（自分のAPIキー）」から、利用者が自分の契約・APIキーでDMDATA公式APIへ直接接続できます。この直接接続で開発者のキー共有や予報の再配信は行いません。[APIキーの設定ガイド](docs/dmdata-setup.md)、[DMDATA管理画面](https://manager.dmdata.jp/)、[公式API資料](https://dmdata.jp/docs/reference/api/v2/socket.start/)を入力欄の近くにも配置します。別途用意する警報・通常地震情報の共有サーバーは[管理者向け手順](docs/dmdata-shared-server.md)を参照してください。初期状態では無効です。

受信区分は「予報」「警報」「予報＋警報」から選べます。「予報＋警報」は1本のWebSocketで両方を購読します。`socket.start` に加え、`eew.get.forecast` と `eew.get.warning` の両方の権限・配信契約が必要です。接続確認で片方の区分しか許可されなかった場合は接続を停止し、片方だけの接続を両方受信中とは表示しません。契約やAPIキーの権限を自動変更することはありません。

公開版ではAPIキーを保存・自動入力・自動接続しません。接続ボタンを押したときだけ、伏せ字入力欄のキーを使用します。認証ヘッダーで固定のHTTPS APIへ送り、キーをURL、GitHub、ログ、ブラウザ保存へ記録しません。接続中と再接続待機中だけページのメモリで保持し、入力欄は接続操作後に消去します。切断・ページ終了・致命的な認証や契約エラーで保持キーも消去します。再読み込み後は再入力が必要です。

公開入力を許可するのはこのプロジェクトのHTTPSオリジン・パスとローカル表示確認用のループバックHTTPだけです。個人用のローカル版の保存処理・保存キーは公開リポジトリに含めません。このページ自身のWebSocketだけを操作し、JQuakeの設定・認証情報・接続には触れません。タブを複数接続すると、その分の接続枠を使用します。契約追加・キー発行・権限・セキュリティ設定変更はアプリから行いません。

DMDATAから有効な接続確認を受けてからEEWの主受信元へ切り替えます。失敗・切断時は既存のYDITS／Wolfx監視へ戻します。認証・契約エラーは自動再試行せず、切断して設定を確認してください。通常の通信失敗は間隔を空けて再接続します。

変換JSONとgzipを扱い、訓練・試験は警報対象にせず、古い速報を現在の速報として動かしません。自動警報音は受信した予想最大震度が5弱以上のときに限り、手動の警報音テストは維持します。PLUMは受信情報の明示フラグを表示するもので、独自のPLUM計算ではありません。震度予測と観測震度を分け、実際の発生時刻・利用可能な震源座標がないDMDATA速報ではP/Sリングを作りません。警報電文の規模・深さは表示しません。

キーの値を含まない入力UI・受信モジュールだけを公開用 `dist/` とService Workerの事前キャッシュへ含めます。API通信とキー・WebSocketチケットはキャッシュしません。実キーでの認証、個々の契約との適合、ブラウザからの実接続は利用者の接続操作まで未確認です。[公式EEWポリシー](https://dmdata.jp/docs/eew/)の、利用者が自分で契約して受信する方式に従い、他の人への再配信サービスは提供しません。

## 現在地の表示

初期設定はONで、起動時にブラウザの位置情報取得を試みます。初回はブラウザの許可が必要です。OSの位置情報設定やブラウザの許可を強制的に変更することはできません。拒否・未対応・取得失敗は状態欄に表示します。「現在地 OFF」にすると取得を停止し、マーカーを消し、次回もOFFにします。「現在地 ON」に戻すと再開します。

現在地はピンクの点と精度範囲で表示し、全国表示の縮尺は変えません。位置の履歴や座標は保存せず、地震情報サービスへ送信しません。位置情報は地震・微振動の検出には使用しません。
